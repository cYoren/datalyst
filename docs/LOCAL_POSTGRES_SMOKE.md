# Disposable study database checks

Status: current

Run `node scripts/test-studies-postgres.mjs` with native PostgreSQL tools (`initdb`, `pg_ctl`, `createdb`, `psql`) installed. The script creates a private `/tmp/datalyst-pg-smoke-*` cluster, listens only on its private Unix socket, and deletes the cluster after stopping it. No existing database, repository dotenv file, PostgreSQL service/passfile or app credential is used. Its subprocess environment is an explicit allowlist and its database URL is generated internally.

The script renders the current Prisma schema offline using an explicit dotenv-free temporary Prisma configuration. It simulates the pre-study schema by removing only study tables inside the disposable database, applies the study migration twice, and tests real services against PostgreSQL. Legacy SQLite migration history is intentionally not replayed; this does not establish a production Postgres baseline or authorize migration deployment.

Checks cover real study creation/recruitment/enrollment, idempotent consent submission, current disclosure hash enforcement, owner/analyst authorization and revocation, numeric pseudonymous output without private identifiers/notes/raw values, RLS and browser-role grants, and withdrawal retaining personal entries while excluding future exports. Two concurrent service calls demonstrably wait on a real study row lock; queued withdrawal completes before the queued export reads participant data. Normal `npm test` skips this opt-in integration test unless both explicit URL variables match the guarded temporary socket format.

Enrollment creates a planning experiment, saves all randomized assignments, then uses the shared experiment lifecycle to activate and freeze the preregistration inside the same transaction as consent and participant creation. It selects the assigned outcome and adherence variable IDs explicitly, rather than relying on future tracker ordering. Signing is attempted only after commit; missing keys leave the frozen plan available with an unavailable signing status. The integration test deactivates/reorders the assigned variable, adds an unrelated first variable, and confirms completion still freezes only the assigned numeric outcome. Study dashboards remain live views of eligible consented study-day observations; a participant's personal completion proof freezes its own dataset at completion.

Study tables deliberately have RLS enabled with no browser policies and no `anon`/`authenticated` grants. Access goes through privileged server-side Prisma and current membership checks. [Supabase RLS guidance](https://supabase.com/docs/guides/database/postgres/row-level-security) explains the independent roles of grants and policies. An older stored protocol/consent hash is never upgraded silently when the disclosure changes: invitations and evidence exports require a new study and fresh consent.

This smoke suite uses synthetic rows on local PostgreSQL; hosted Supabase grants/advisors, staging migration review, real-device flow, research ethics and external AI consent review remain rollout checks. It does not contact Supabase or production.
